# Contributing to Unicorn Who Dev public projects

Thank you for taking the time to inspect or improve one of the public repositories.

## Choose the right repository

Open issues and pull requests in the repository that owns the relevant code:

- [Image Genial](https://github.com/unicorn-who-dev/image-genial-codex-picture-editor) — Codex-native image-editing workflow.
- [Splat Facade Baker](https://github.com/unicorn-who-dev/splat-facade-baker) — lightweight 2.5D asset pipeline.
- [OmniStream for Codex](https://github.com/unicorn-who-dev/omnistream-for-codex) — local Omniverse viewport streaming.

Commercial products and private-source repositories are not managed through public feature requests unless their product site explicitly links to a public tracker.

## Before opening an issue

1. Check the repository README, known limitations and existing issues.
2. Describe the user-visible problem or intended result before proposing an implementation.
3. Include the operating system, relevant application versions and a minimal reproduction when reporting a bug.
4. Remove credentials, private images, prompts, datasets, generated artefacts and machine-specific paths.

## Pull requests

Keep changes focused and preserve the stated product boundaries. A pull request should include:

- the problem being solved;
- the user-visible effect;
- the files changed;
- validation commands and results;
- limitations that could not be tested locally.

Repository-specific contribution rules take precedence over this default file.

## Licences

Each repository has its own licence. Public visibility does not automatically mean open-source reuse is granted. Check the repository `LICENSE` file before copying, redistributing or integrating code.
